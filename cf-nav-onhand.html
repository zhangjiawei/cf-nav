本次部署步骤

  1. 在 GitHub 将上游仓库 Fork 到 zhangjiawei/cf-nav，保留上游来源和 lineagett 分支。
  2. 在 Cloudflare Workers KV 创建 cf-nav-card-order 命名空间。
  3. 向 Fork 提交 wrangler.jsonc：Worker 名 cf-nav、入口 workers.js、兼容日期及 CARD_ORDER KV 绑定。该文件是公开部署配置。
  4. 在 Workers 和 Pages 选择「Continue with GitHub」并连接 zhangjiawei/cf-nav，项目名 cf-nav，部署命令 npx wrangler deploy，无需构建命令。Cloudflare 建立 Git 构建连接并完成首次部署。
  5. 在 Worker「设置 → 运行时变量和密钥」的生产环境添加 ADMIN_PASSWORD 与 JWT_SECRET，类型均选择「密钥」，保存并部署。创建时的「构建变量」不能代替运行时密钥。
  6. 在 Worker「域」中选择「添加域名」，区域选 izjw.top、子域名填 nav、启用对象为生产。Cloudflare 创建对应的自定义域绑定。

密钥值不在 GitHub、Wrangler 配置或本手册中。管理员密码通过部署会话单独交付；请保存在密码管理器。JWT 密钥仅保存在 Cloudflare，重设它会让已有登录令牌失效。

日常维护

更新源码

在 cf-nav 仓库的 lineagett 分支提交修改；Cloudflare 的 Git 构建连接会按仓库变更重新运行 npx wrangler deploy。在 Worker「部署」页检查新构建状态，再打开自定义域核验。同步上游前先检查上游改动与本仓库部署配置是否冲突。

更换管理员密码

在 Worker「设置 → 运行时变量和密钥」编辑生产环境 ADMIN_PASSWORD，使用至少 8 字符的新值，保存并部署。不要把密码写入仓库、提交消息或本文档。JWT_SECRET 至少 32 字符。

数据与故障

书签数据保存在 cf-nav-card-order KV 中，更新 Worker 不应删除该命名空间。若页面显示配置错误，先检查生产环境的两个运行时密钥和 CARD_ORDER 绑定；若域名不可达，检查 Worker「域」里的 nav.izjw.top 状态和 izjw.top DNS 记录。
